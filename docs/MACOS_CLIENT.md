# macOS Client (Apple Silicon)

The current-main client supports Apple Silicon Macs on macOS 11 or newer. It
uses the same enrollment API and FRP 0.71.0 pin as the Linux client. Intel Macs
are not supported.

## Requirements

- Apple Silicon (`arm64`)
- macOS 11 Big Sur or newer
- `sudo`, launchd, `curl`, `openssl`, `tar`, and `shasum` (OS tools)
- Network access to the Server and, when no compatible Python is present,
  the pinned upstream Python Build Standalone release over authenticated HTTPS.

The Zero-Touch Bootstrap provisions a product-owned, SHA256-pinned Apple
Silicon Python runtime when needed, without requiring Homebrew or Command
Line Tools. It does not modify the system Python, enable Remote Login, change
the firewall, or create users. Manual installation still requires a
compatible existing Python. The managed interpreter is under the Agent state
root and is removed by Agent uninstall.

## Layout

Runtime state, configuration, identity, libraries, and the pinned `frpc`
binary live below `/Library/Application Support/drlink`. The
LaunchDaemon is
`/Library/LaunchDaemons/com.datarelay.drlink.frpc.plist`.

The user-facing `drlink` command is installed below the prefix reported by
`brew --prefix`, with `/usr/local` as the fallback. Internal compatibility
helpers are not part of the public CLI. The root LaunchDaemon never executes
a Homebrew-prefix binary.

## Install and enrollment

Use the client enrollment command generated by your Data Relay Link server:

Copy only the Server-generated command. The Linux/macOS fixed six-character target is `curl -kfsS https://remote.xdr.ooo/A3xK9m|sudo bash`. Public/private HTTPS share this form, with no DataRelay prerequisite. All subsequent operations use the Bootstrap; see [the canonical contract](ZERO_TOUCH_REGRESSION_CONTROL.md) for the initial trust risk and independent enrollment gate. Native qualification is pending.

The shared bootstrap detects Darwin independently, rejects Intel/Rosetta
shells, downloads `frp_0.71.0_darwin_arm64.tar.gz`, and verifies SHA-256
`45be02b186860d375ed49a8941ae9569628a54bf14e67fc36b29c98c99dabcc6`.

## Service control

Normal client commands use `sudo drlink`. Everyday lifecycle examples:

```bash
sudo drlink show status
sudo drlink system pause
sudo drlink system resume
sudo drlink system restart
sudo drlink system autostart
```

Direct launchd inspection for troubleshooting is:

```bash
sudo launchctl print system/com.datarelay.drlink.frpc
```

Daemon output is written to `logs/frpc.out.log` and `logs/frpc.err.log` under
the state root.

## Uninstall

Run `sudo drlink system uninstall`. Local files and the LaunchDaemon are
removed. Server-side enrollment records and port reservations are intentionally
retained and must be released explicitly on the server with:

```bash
unset managed-host <HOST>
```
