## LPERF-1/4 — 100-Agent multi-host MCP 1 versus 6 workers

Raw immutable lab logs: /home/aella/drlink-validation/lperf-20261123/mcp-workers1-c72b704f and mcp-workers6-c72b704f.

Source HEAD for BOTH: c72b704f5996d6af73e2724634ae6e0a5b676f77 (clean). 100 synthetic AgentLoop workers, 5 Agent child processes, 2 Agent-facing management server child processes, real Bridge worker processes, 3 rounds. Calls distributed across up to 30 simulated hosts.

| Calls | 1 worker p95 / p99 | 6 workers p95 / p99 |
| --- | ---: | ---: |
| 1 | 105 / 105 ms | 42 / 42 ms |
| 10 | 320 / 340 ms | 137 / 140 ms |
| 30 | 1154 / 1157 ms, SLO UNMET | 388 / 425 ms, SLO MET |

30-call p95 66.4% faster with six processes and no wrong-target/error outcome in those runs. Prior AUD-21 D1–D7 includes multi-process dispatch; reused, not rewritten.

Six-worker peak aggregate worker PSS ~134 MiB and per-worker RSS peak ~36 MiB (30 calls), worker CPU ~21.9 ms/call. Legacy one-worker child-only metric reports zero because the server is in the supervisor itself: that is an instrumentation limitation, not zero CPU or RAM. Aggregate CPU reduction NOT PROVEN.

An opt-in DRLINK_MCP_WORKERS=auto product policy is being tested: six workers only when effective CPU >=8 and memory >=2 GiB; two if 4..7; otherwise one. Default remains one, explicit values prevail. Any installed-service tuning requires separate authorization.
