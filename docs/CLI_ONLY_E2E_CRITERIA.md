# CLI-only E2E criterion groups

The complete original scenario bodies, shared repetition counts, native platform requirements, and real public-action evidence remain authoritative. A group PASS means **all** its corresponding original assertions were exercised with exact-candidate receipts, not one representative command. This is a resumable progress index, not a reduced acceptance contract. A newly discovered applicable variant is recorded within its group. Unsupported subcases are documented within the group; missing claimed features are findings, not exclusions. Record subcase receipts before the parent verdict. Do not consult implementation as the acting persona.

Use the owner-configured test host inventory and actual product actions; no standalone connection checks. Reuse compatible same-run evidence across groups. Historical evidence can prioritize retests but cannot qualify a changed HEAD.

## Execute and resume

Use the existing private RUN_ID. New runs initialize both the original 116-row TSV and the frozen 321-group JSON; old runs remain readable and unchanged.

- Initialize once: `python3 tools/cli_only_e2e_inventory.py init --run-root <RUN_ID> --source-head <SHA>`. Add `--extended-soak` only when requested.
- After real actions, record each group with `record-criterion --criterion-id U-001.01 --result PASS --target <HOST> --installed-head <SHA> --actual-command <REDACTED_COMMAND> --evidence <RELATIVE_RECEIPT>` and the same run root. Receipt must contain every applicable assertion, actual exit code, observed effect and cleanup as required by the canonical contract.
- Use `remaining --run-root <RUN_ID>` to retrieve unresolved groups and parent IDs. Do not repeat frozen PASS groups unless a new candidate or incompatible state requires it. Blocked groups need real action/dependency receipts and precise reasons.
- Record a parent verdict only after group evidence is complete; the tool refuses positive verdicts with missing groups or altered receipts. P-020 N/A requires `INFRASTRUCTURE_UNSUPPORTED:` plus actual evidence; absence of access is not that condition. A completed functional performance parent without an approved numeric threshold uses `FUNCTIONAL_PASS_NUMERIC_UNQUALIFIED` and `NO_APPROVED_NUMERIC_SLO:` with the reason and evidence. An incomplete measurement stays `MEASURED_NOT_QUALIFIED` or PARTIAL, not functional PASS.
- The CLI functional gate, numeric performance gate and strict all-applicable gate are separate. Never equate any of them with full 116-ID release acceptance. If a performance threshold is already approved, apply it. Actual optional test failures are still reported.
- On a candidate change, preserve the old RUN_ID and use the existing delta-triage tool to prioritize affected checks; final exact-candidate qualification still requires current evidence. Do not copy historical PASS into the new ledger.
